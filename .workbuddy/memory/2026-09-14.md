### ckpt_path 加载契约核实（避免 40min 白等）
注意 `load_from_name` 定义在 **`cn_clip/clip/utils.py:106`**（不是 `clip/__init__.py`；`inspect.getsource` 才暴露真相，`dir()` 里看不到 `_MODELS`/`_MODEL_INFO`）。核实结论：
- `_MODELS["ViT-H-14"] = ("chinese-clip-vit-huge-patch14", "clip_cn_vit-h-14.pt")`、`_MODELSCOPE_ORG = "AI-ModelScope"` → **我们下的文件与 cn_clip 自身下载目标完全一致**。
- `_MODEL_INFO["ViT-H-14"]["struct"] == "ViT-H-14@RoBERTa-wwm-ext-large-chinese"` → 与 `clip_backend.py:278-283` 用 `vision_model_name + "@" + _CN_TEXT_MODEL_NAME` 构造的串**精确匹配**。
- 本地 .pt 走 `elif os.path.isfile(name)` 分支，**要求** `vision_model_name`/`text_model_name`/`input_resolution` 三者齐备 —— `clip_backend.py` 已全部提供。
- `create_model` 里 `model.load_state_dict(sd)` **默认 strict=True**，外加两份 `model_configs/*.json` 的 `assert os.path.exists` → **模型名配错是「响亮失败」，不是静默降级**（符合本项目铁律）。已确认 `ViT-H-14.json` 与 `RoBERTa-wwm-ext-large-chinese.json` 存在。
- ⚠️ **隐性耦合**：`_CN_TEXT_MODEL_NAME` 硬编码为 **large**，仅对 ViT-H-14 成立（ViT-B-16 / ViT-L-14 的 struct 都是 base）。换视觉塔必须同步改文本塔，否则报错。
- ⚠️ `CLIP_CN_MODEL_NAME` 语义**双重**：ckpt 路径下当「架构串」，下载路径下当 `load_from_name` 的 name（cn_clip 也吃架构串）—— 两条路径都传 `"ViT-H-14"` 恰好都对，但语义不同，改值需同时考虑。
