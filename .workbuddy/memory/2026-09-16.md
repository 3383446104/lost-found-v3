## 相似度偏低（45%）归因分析 + 发现时间衰减失效 Bug（lead）

用户问「为什么文本查找相似度这么低」（截图：text=白色蓝牙耳机 / 类别=电子产品 / 位置=图书馆 → 1 条结果 45%）。
用真实模型 + 真实库向量逐阶段复现（只读）。

### 45% 的精确构成（item64，用户看到的那条）
| 阶段 | 值 | 说明 |
|---|---|---|
| `sim_tt`（q文·t文） | **0.9557** | 几乎同一句话 → 匹配完全正确 |
| `sim_t2i`（q文·t图） | 0.2724 | CLIP 跨模态余弦天然低 |
| 动态归一化权重 | 文-文 **0.30** / 跨模态 **0.70** | 纯文查询无图无色 → 只剩两通道，0.15/0.5 与 0.35/0.5 |
| base 加权分 | 0.4774 | **0.7×0.2724 + 0.3×0.9557** ← 主因 |
| 阶段1 类别同 +0.05 / 位置异 -0.04 | 0.4874 | |
| 阶段2 时间衰减 | **×1.0（失效，见下）** | |
| 阶段5 跨模态惩罚 | ×0.9311 | 轻微 |
| **最终** | **0.4538 ≈ 45%** | |

**结论**：不是检索错误，而是**分数标度问题**——文-文通道几乎满分但只占 30%，跨模态通道占 70% 而余弦仅 0.27，加权后被拉到 0.48。跨模态通道绝对低（0.2~0.3 量级）是 CLIP 类模型固有特性（与真实标定观察一致）。

### ⚠️ 附带发现：**时间衰减阶段（阶段2）完全失效**（真实 Bug）
- `items.py:596-611`：`datetime.fromisoformat("2026-07-02 01:06:44")` **成功**返回 **naive datetime** → 循环 `break`（不试第二个格式）
  → `datetime.now(timezone.utc) - target_date` 抛 **TypeError（naive − aware）**
  → 外层 `except Exception: days_old = 0` 吞掉 → **days_old 恒 0 → decay 恒 1.0**。
- 实测对比：正确应为 76 天 → decay = max(0.2, 1−76/90) = **0.2** → item64 得 **9%**；线上实际 **45%**（= 9% ÷ 0.2，完全吻合）。
- 影响：① 时效性排序失效，老物品分数虚高；② 若修复，纯文搜分数集体降至 ~1/5，**手动阈值 0.35 会把现有结果全部滤掉** → 必须与阈值重标同步进行（且既有标定全部是在"无衰减"状态下产出的）。
- 状态：**已确认，未修复**（涉及阈值重标，待用户决策）。

## 打分通道收敛为三通道等权 + 颜色废弃（用户决策，lead 实施）

用户："我想搞文-文，图-文，纯图，三个评分通道" → 澄清后确认：**三通道各自独立等权（各 1.0）+ 颜色彻底废弃 + 跨模态双向合并**。

### 实现（口径极干净：等权时公式 = 可用通道算术平均）
- `config.py`：三通道权重全 **1.0**，`MATCH_W_COLOR=0.0`（键位保留兼容）。
- `clip_service.compute_weighted_similarity`：channels 收敛为 3 项；颜色不参与；**`color1/color2/color_weight` 形参保留但一律忽略**（冻结接口兼容 —— conftest 依赖方法名，删签名会连锁）；`compute_color_similarity`/`get_color_histogram` 方法保留但不再被打分调用。
- `items.py` / `match_service.py`：移除颜色读取与回退计算（**顺带省 27 维直方图计算 + 磁盘 IO**）。
- `calibrate_thresholds.py`：grid 四维 → 三维；`summarize_grid` 去掉颜色直方图；`score_pair` 不传色；`_FakeEncoder/_ServiceEncoderAdapter.encode_color` 与 `_EncoderCache.color` 删除。
- 文档：PROJECT（§9.2/§3.3/§8.4/版本清单）/README（简介/功能/架构图/设计系统）/SRS（FR-MATCH-03/04/§8.2）现行口径同步（19 处，脚本批量、每处校验 count==1）。

### 实测效果（真实模型 + 真实库）
