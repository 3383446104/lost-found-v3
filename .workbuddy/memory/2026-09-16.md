## 前端「功能无法实现」两轮排查（lead）

用户隔两天回来报「前端代码有问题，功能无法实现」→ 分两轮定位、修复。

### 第一轮：服务未运行（非代码问题）
- `git status` 干净、`vite build` 通过、**前端 22 个 API 调用与后端 OpenAPI 100% 对齐**（脚本比对）、关键接口实测 200 → 判定代码无问题。
- 真因：**前后端进程都没在跑**（两天前的实例早已退出）。另提醒用户勿用 file:// 双击 `dist/index.html`（SPA 路由与 API 全废）。
- 恢复：后端经 explorer 启动 bat 长期驻留；前端用 Bash 后台任务拉起。

### 第二轮：MatchView 缺 `computed` 导入 → `/match` 整页空白（真实代码缺陷）
用户发截图：`/match` 路由激活（导航高亮）但**内容区完全空白**（导航/页脚属 layout 层，正常）。

- 根因：`MatchView.vue:163` 用 `computed()`，第 133 行 `import { ref, onMounted, onUnmounted } from 'vue'` **漏了 computed** → `<script setup>` 执行抛 `ReferenceError` → 整个视图渲染中断。
- 引入点：`97d4fad`（v3.5.0 主体提交，加 50 字提示功能时新增 `textCharCount` computed 却漏 import）。
- **同类第二处**：`ItemDetailView.vue:108` `<Checked />` 但 icons 导入缺 `Checked` → 图标静默不渲染（Vue 只告警不炸）。
- 修复：两处补导入。提交 `f79e573`。
- 验证：全量 SFC 检查 0 问题（修复前 2 处）+ vite 转译产物核对（import 均含所需标识符）+ `vite build` ✓ 2.17s。

### ★ 核心教训（写入 MEMORY.md）
1. **「构建通过」≠「运行时可用」**：未定义标识符在 ESM 下是合法全局读取，rolldown/vite build **不报错**（本次 build 一直绿），只有浏览器执行到那行才抛。**前端改动必须做一次真实浏览器渲染验证**——v3.5.0 收口时我做了 209 后端用例 + 真实模型 + `/match` HTTP 200，唯独没做浏览器渲染验证，导致此缺陷潜伏两天。
2. **新增工具**：`lost-found-frontend/scripts/check_sfc_integrity.py`（全量扫 `src/**/*.vue`：Vue API 导入 / 模板组件图标导入 / 模板函数定义；退出码 0/1）。改前端后应跑一次。
3. 定位此类问题的高效路径：**用户截图给症状 → 读组件源码找模板引用 vs script 定义的不一致**，比盲目跑测试快得多。
