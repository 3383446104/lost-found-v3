# 评测集与标注规程（v3.5.0）

本目录存放阈值标定 / 权重收敛所用的**评测集** `eval_set_v3.5.0.json`。
当前评测集基于 `backend/lost_found.db` 中**真实存在的物品**构造，经 2026-09-14 扩充轮后共 **84 对 = 42 正 + 42 负**（原始 70 对见 §8 历史记录）：
其中 **50 对为纯文查询**（含 §8 补入的 10 对同类硬负样本），**20 对为图片查询**
（`query.image` 非空：8 对 img→t_text + 12 对 img→img）——详见 §7 / §8。

> ⚠️ **有效标定集 = 36 正 / 42 负（n=78）**：img→img 的 6 条正样本（P25–P30）为「同图自比」退化对
> （`sim_ii ≡ 1.0`），**已在标定计算中剔除**（详见 §7.4）。引用阈值/Recall 时请以有效集为准。

**要复现标定，须满足其一**：

> 设计取舍说明：我们**选择不把真实数据入库**（隐私优先），代价是评测集不可随仓库分发。
> 若需 CI 可复现的标定，应另建一份**自包含的合成评测集**（图片 + 标签一并入库），
> 但那样测的是合成分布，与生产分布存在偏差——当前未做此取舍。

## 2. 文件结构

```jsonc
{
  "version": "v3.5.0",
  "model_backend": "cn_clip",
  "model_name": "ViT-H-14",
  "label_rule": "人工判定：查询与目标是否指向同一实物。相关=1 / 不相关=0。",
  "pairs": [
    {
      "id": "P01",
      "label": 1,                    // 1 = 相关；0 = 不相关
      "category": "电子产品",          // 取自 DB 的 7 个真实类别名（此处为【目标物品】的实际 category）
      "query":  { "text": "…", "image": null },
      "target": {
        "item_id": 64,               // 真实 DB 主键
        "item_ref": "uploads/079e….jpg",  // 真实 image_path（相对 backend/）
        "text": "蓝牙耳机 白色蓝牙耳机"    // = title + ' ' + description（对齐线上 text_vector 源）
      }
    }
  ]
}
```

- 查询侧**以纯文字查询为主（50 对，`query.image = null`）**——本次核心修复即「描述搜图」；
  另含 **20 对图片查询**（`query.image` 非空，见 §7），用于压 `sim_ii` / `sim_cross_i2t` 两个
  此前未被覆盖的通道。
- `target.text` 为 `null` 表示「目标仅有图片、无文字」——**当前共 12 对**此类样本
  （即 img→img 组），覆盖「目标仅有图片」的 t_text 缺失路径（见 §4 / §7）。
- 每对可含可选字段 `kind`（`img2text` / `img2img`），仅供人工阅读，脚本忽略。

## 3. 标注硬约束（正样本）

- **查询不得包含目标 `title` 的原词**：否则退化为关键词 LIKE 匹配，失去语义检索评测意义。
  例：目标 `title = 蓝牙耳机`，查询写作「白色的小型无线听音设备，配一个方形充电仓」。
- 正样本查询为该物品的**改写描述**（口语化、换语序、只描述外观特征）。
- 负样本为**跨类别错配**（如「电子产品查询 × 证件卡片物品」「书籍文具查询 × 电子产品物品」）。

### 3.1 查询长度设计（对齐模型真实可用窗口）

Chinese-CLIP 文本塔 `context_length = 52`，去掉 `[CLS]` 与 `[SEP]` 后，**实际可用 = 50 个汉字**；
超长输入**静默截断**（只保留前 50 字，不抛异常）。因此：

- **长描述查询落在 33~48 汉字**区间（当前 10 条正样本满足），既覆盖 AC-F2「长中文描述」场景，
  又确保关键语义完整落在模型可用窗口内；
- **不构造 >50 字的查询**去测「超长」——那实际测的是「截断后的前缀」，并非长语义。
- 同理，物品侧文本（查询 `title + description`）超过 50 字的尾部对文本向量无贡献，
  描述应把关键特征前置。

## 4. 覆盖面声明（重要）

- 真实库仅有 4 个类别有物品：`电子产品`、`钥匙门禁`、`证件卡片`、`书籍文具`；
  **没有** `包袋箱包` / `服装配饰` / `其他` 条目——这三个类别**只能作为跨类别负样本出现**，
  无法构造其正样本。
- 因此本评测集的类别覆盖是**不均衡**的（电子产品占比最高），标定出的阈值对少数类别
  的代表性有限。

### 4.1 打分通道覆盖（v3.5.0 补齐后）

`compute_weighted_similarity` 的四条跨模态/同模态通道在本评测集中的覆盖情况：

| 通道 | 表达式 | 覆盖对 | 说明 |
|------|--------|:--:|------|
| `sim_text_text` | `q_text · t_text` | 50 | 纯文搜（主场景） |
| `sim_cross_t2i` | `q_text · t_img` | 50+8 | 纯文搜命中带图目标；img→text 组的 target 无图时该通道关闭 |
| `sim_cross_i2t` | `q_img · t_text` | 8 | **本次新增**：img→text 组（`query.image` + `target.text`） |
| `sim_img_img` | `q_img · t_img` | 12 | **本次新增**：img→img 组（`query.image` + `target.item_ref`） |

> 修复前 `sim_ii` 与 `sim_cross_i2t` **从未被评测集压过**（原 40 对 `query.image` 全为 `null`）；
> §7 新增的 20 对图片查询补齐了这两条通道。

### 小样本免责（必须遵守）

> `n = 70`（**有效标定集 64 = 24 正 + 40 负**），**置信区间很宽**，本评测集**仅作保守起点**；
> **不得**据此表述为「已可靠标定」或「阈值已收敛」。
> 阈值与权重须随真实数据增长**持续复标**；上线前请以扩充后的更大评测集复跑报告。

## 5. 如何扩充

1. 用户后续新增物品入库（`items` 表增长）后，重新导出物品清单。
2. 为每条物品写 2–3 条**改写查询**（遵守 §3 硬约束），加入正样本。
3. 用不同物品的查询 × 目标**跨类别交叉配对**，补充负样本。
4. 拟扩充图片查询：直接复用 `backend/uploads/` 中**已存在的真实图片**
   （`item_ref` / `query.image` 相对 `backend/` 书写）；如确需独立评测图片，
   再放入 `backend/eval/uploads/` 并把路径写为相对 `backend/` 的引用。
   `query.image` 覆盖 img→text 与 img→img 两类（见 §7）。
5. 先做**结构自检**（不加载模型、秒级返回；CI 亦可跑）：

   ```bat
   venv\Scripts\python.exe scripts\calibrate_thresholds.py --stats
   ```

   会打印：总数 / 正负样本 / `query.image` 非空（img→text、img→img 拆分）/
   纯文查询 / `target.text=null` / 查询文本长度 min·max·>50 / 标题词泄漏 /
   引用图片存在性（缺失即报错路径）。
6. 运行标定：

   ```bat
   venv\Scripts\python.exe scripts\calibrate_thresholds.py --with-penalty --grid ^
       --eval-set eval\eval_set_v3.5.0.json
   ```

7. 将报告中的建议阈值回填 `.env`；若 `Recall@3 < 0.90`，按报告「阻塞性发现」处理。

## 7. 图片查询扩展（D-B2：补齐 `sim_ii` / `sim_cross_i2t` 通道）

### 7.1 背景

修复前的 40 对**全部为纯文查询**（`query.image = null`），因此只压到了
`sim_text_text` 与 `sim_cross_t2i` 两条通道；**`sim_img_img`（q_img·t_img）与
`sim_cross_i2t`（q_img·t_text）从未被任何评测对触发**。§7 新增 20 对图片查询补齐之。

### 7.2 扩充决策：「扩充」而非「替换」

保留原 20 对纯文正样本（核心修复「描述搜图」场景**不流失**），把总数由 40 扩到 **60**
（30 正 / 30 负）。理由：替换会牺牲主场景覆盖面，而扩充可两者兼得；
代价是评测规模变大、纯文/图片两类样本按 40:20 混合，报告需按通道理解 Recall。
**注意**：其中 6 条 img→img 正样本（P25–P30）为退化对，**标定计算时剔除**（见 §7.4），
故 §7 完成时**有效标定集 = 24 正 / 30 负**。

> **后续（§8）**：为解开 `AUTO`/`EMAIL` 阈值标定被「同类近重复**假阳性**」顶住的问题，
> 又补入 **10 对同类硬负样本（N31–N40）**，总数达 **70 对 = 30 正 / 40 负**，
> 现**有效标定集 = 24 正 / 40 负（n=64）**。

### 7.3 新增对的构成（共 20 对，全部复用库中 6 张真实物品图）

| id | label | 类型 | `query.image` | `target.item_ref` | `target.text` | 主要压测通道 |
|----|:--:|------|------|------|------|------|
| P21–P24 | 1 | img→text | 物品**自身**图 | `null` | 物品自身文本 | `sim_cross_i2t` |
| N21–N24 | 0 | img→text | 本类物品图 | `null` | **别类别**物品文本 | `sim_cross_i2t` |
| P25–P30 | 1 | img→img | 物品**自身**图 | 物品**自身**图（同一文件） | `null` | `sim_img_img`（**退化·已剔除**，见 §7.4） |
| N25–N30 | 0 | img→img | 本类物品图 | **别类别**物品图 | `null` | `sim_img_img` |

- 构成满足要求：img→text **8 对**（正 4 / 负 4）、img→img **12 对**（正 6 / 负 6）；
- `target.text=null`（「目标仅有图片」）**共 12 对**——覆盖 t_text 缺失路径（D-B2(a)）；
- **P25–P30 为「同图自比」退化对**（`query.image ≡ target.item_ref`，`sim_ii ≡ 1.0`），
  打标 `degenerate_self=true` 并**从标定计算剔除**（见 §7.4）；§7 完成时有效标定集 = 24 正 / 30 负，
  现为 **24 正 / 40 负**（含 §8 的 10 对硬负样本）；
- 文件真实存在性由 `--stats` 校验（**在持有生产数据的机器上**当前 6 个引用、缺失 0）；
  ⚠️ **新克隆上会缺失 6 个** —— 图片与 DB 均不在版本控制内，见 **§1.1 可复现性前提**。

### 7.4 方法论结论：img→img 真实正样本在当前数据下不可构造（已从标定剔除）

**结论：`sim_img_img` 的「真实」正样本在当前数据条件下无法构造**——每个真实物品只有 **1 张**
照片，而真实的「以图搜图」场景需要「用户自己拍的第二张照片」；我们没有第二张，只能用同一文件
同时充当 query 与 target，即「同图自比」，其 `sim_ii = v·v ≡ 1.0`（恒等于满分）。

这**不是「弱正例」，而是恒等退化**。若纳入标定会造成两个实质危害：

1. **虚高 Recall**：这 6 对在排序中必然 `rank = 1`，白送 6 个命中；
2. **向下拖低 `auto` 阈值（生产风险）**：`auto` 口径为 `lowest_with_precision(0.90)`——
   升序取首个 `Precision ≥ 0.90` 的阈值。6 个恒为 1.0 的正样本会抬高中等阈值处的 Precision，
   使 0.90 被**更早**满足 → 返回阈值**偏低** → 线上更多物品被自动判为匹配，
   而该 0.90 保证其实是被退化样本撑起来的假象（30 正里有 6 个＝**20%** 注水）。

**处理（已实现）**：

- P25–P30 打标 `"degenerate_self": true`；
- `scripts/calibrate_thresholds.py` 在 `evaluate()` / `suggest_thresholds()`（经入参过滤）/
  `_recall_ranks()` / `grid_search()` 四处**在计算层面排除**这 6 对；
- **但仍单独打分并打印**（`--degenerate-check`）确认 `sim_ii == 1.0`，保留其
  「`sim_ii` 通道已接通」的**接线自检**价值——**它不是评测数据**；
- **不删除**这 6 对：删除会丢失「`sim_ii` 曾被跑通」的记录，打标可两者兼得；
  也**不**采用「query 用 A 图、target 同 A 图却标负」之类的造法——那是**错误的标签**。

**有效标定集 = 24 正 / 40 负**（原始 70 对剔除 6 个退化正例）。正负**不再平衡是故意且保守的**：
负样本更多只会让 `Precision ≥ 0.90` 更难达到 → `auto` 阈值更高 → 线上更安全。

**`sim_ii` 的可用性与区分度由负样本验证**：N25–N30（跨类别、**不同图**）给出非退化的 `sim_ii`
取值，用于确认该通道对「不同物品」有区分能力；而 img→img 的**同图接线**由 `--degenerate-check`
确认。真实「同类别不同实例」的 img→img 正样本，须待**每个物品有 ≥2 张真实照片**后再补。

**另两条保留局限**：

- img→text 正样本的锚点为纯文本：`query.image` 与库中**同一物品（带图锚点）**会同时存在于候选集，
  可能使该正样本 rank 落在物品锚点之后（锚点设计使然，非模型缺陷）→ 这类样本的 Recall@K 应保守解读；
- 样本多样性有限：仅 6 张真实物品图。
- 本扩展**未新增、未下载任何图片**，全部复用 `backend/uploads/` 既有真实图。

## 8. 同类硬负样本补充（N31–N40，为解开 AUTO/EMAIL 标定）

### 8.1 动机

真实权重下测得：跨类别检索已解（`Recall@3 = 1.0`，且 5 个 rank-2 误排**全是同类近重复**），
但 `MATCH_THRESHOLD_AUTO`（Precision ≥ 0.90）**无解** —— 默认配置下 PR 曲线 Precision 上界仅 **0.6129**。
根因是**评测集的负样本全是易分「跨类别错配」**，缺**同类近重复假阳性**，
于是「高相似但不同物」这一最危险的线上场景（两副白色蓝牙耳机）在评测集里**根本不出现**。
故补入 10 对同类硬负样本。

### 8.2 构成（共 10 对，`hard_negative: true`；均标注 `reused_query_from`）

构造法：**复用既有正样本的查询文本，只把 `target` 换成另一件物品**——
查询语义完全合法（仍是对某件真实物品的合理描述），但标签为 0（指向的是不同的实物）。

| id | 复用查询 | 查询语义 | 目标 | 类型 |
|----|------|------|:--:|------|
| N31–N34 | P01–P04 | 描述 item64（耳机） | item68（耳机） | **同类别近重复** |
| N35–N37 | P05–P07 | 描述 item68（耳机） | item64（耳机） | **同类别近重复（反向）** |
| N40 | P01 | 描述 item64（耳机） | item73（充电器） | 同类别不同物（电子产品） |
| N38 | P08 | 描述 item67（房卡） | item77（学生证） | 卡片类混淆 |
| N39 | P15 | 描述 item77（学生证） | item67（房卡） | 卡片类混淆（反向） |

### 8.3 结果与解读

- **`Recall@K` 完全不变**：`0.7917 / 1.0 / 1.0 / 1.0`（补入前后一致）——
  说明**跨类别检索早已解**，同类近重复才是残差；
- **Precision 上界进一步下降**（默认配置下由约 0.77 降至 **0.6129**）——
  这是**预期且正确**的：负样本更难 ⇒ 同等阈值下假阳性更多 ⇒ Precision 更低；
- 因此 **`AUTO` / `EMAIL` 仍无解（`None`）**，且**不得**为「凑出 0.90」而放宽口径。

> ⚠️ **不可与补入前直接比较绝对值**：正负比由 30/30 变为 30 正 / 40 负，Precision 口径随之改变。
> 只能比较**「同一权重在不同负样本构成下是否仍然成立」**（答案：成立 —— 见
> `docs/review/threshold-calibration-v3.5.0.md` §5 的合格集合分布）。

### 8.4 遗留

真实「同类别不同实例」的**正**样本（同一物品的第二张照片）在当前数据下仍不可构造
（每个物品仅 1 张图，见 §7.4）；同类近重复的**负**样本本轮已补齐，但样本量仍小（n=64 有效集），
阈值/权重结论**仍属保守起点**，须随数据增长持续复标。

## 9. 覆盖盲区：字面查询（v3.7.0 补充度量）

### 9.1 盲区是什么

§3 的正样本硬约束是「**查询不得包含目标 title 的原词**」。这条约束保证了评测的是**语义改写能力**，
但同时也让评测集**在结构上无法覆盖**生产环境最常见的一类查询：**用户只输入两三个字的名词**
（「房卡」「水杯」「耳机」）。这类查询有三个向量通道都答不好的特性：

1. **字面即答案**：标题完全相同就该是满分，不需要语义泛化；
2. **短文本各向异性**：两字词之间的余弦普遍落在 0.75~0.85，向量无法区分「房卡」与「学生证」；
3. **字面特征是唯一确定性证据**：`literal_hit` 在生产上贡献很大，而在本评测集上**恒为 0**。

### 9.2 后果（引用本评测集结论时必须说明）

- 「v2 相对 legacy 的提升」在本评测集上被**低估**（字面通道全程未触发）；
- 「标题通道字面门控」的收益在本评测集上**完全测不出**，甚至显示为轻微下降
  （P@手动 0.8250 → 0.8049，仅 1 个样本差异）；
- 因此**不得**据本评测集否决门控。门控的决策依据是
  `scripts/eval_literal_pairs.py` 在真实库上的混淆度量（越阈值率 61.9% → 19.0%）。

### 9.3 补齐方式（当前方案：旁路度量，不改本集）

保留本评测集的「无语义泄漏」纯度，另设一个**不依赖人工标签**的旁路指标：

```bat
venv\Scripts\python.exe scripts\eval_literal_pairs.py
```

它遍历真实库中标题互不包含的物品对，统计「理应不相关却越过手动阈值」的比例（FP 下界）。
后续若要正式纳入标定，应按 §5 补一份**字面查询子集**（`literal_queries: true`），
并在 `calibrate_v2.py` 中按子集分别报告 P/R —— **已于 §10 的 v3.7.0 评测集落地**。

## 10. v3.7.0 自包含评测集（素材图重建）

### 10.1 为什么要另建一份

v3.5.0 集有三个**结构性**问题，都不是「再多标几对」能解决的：

| 问题 | 后果 |
|---|---|
| 图片在 `backend/uploads/`、标签锚定 `lost_found.db`，两者均被 gitignore | 新克隆上 6 个引用全缺失，**评测集不可运行**（§1.1） |
| 只有 6 件真实物品、4 个类别 | `包袋箱包 / 服装配饰 / 其他` **零正样本**（§4） |
| 正样本硬约束「查询不得含 title 原词」 | 生产最常见的**两三个字查询**（「房卡」「耳机」）整类缺席（§9） |

### 10.2 构成

- **69 件物品 / 7 个类别 / 293 对**，全部来自桌面素材图（`校园失物招领-素材图`），
  经人工认物后写入清单；
- 图片复制到 `eval/images/<slug>/<原文件名>`（**ASCII 目录名**，避免编码差异；
  该路径不被 `.gitignore` 排除，可随仓库分发）；
- 每件物品一条 `title` + 一条 `desc`，`target.text = title + " " + desc`（与线上 `text_vector` 源一致）。

| 前缀 | subtype | 标签 | 数量 | 含义 |
|---|---|:--:|:--:|---|
| `P` | `rewrite` | 1 | 69 | 改写查询 → 目标图（查询不含 title 原词） |
| `L` | `literal` | 1 | 69 | **字面查询**（查询 == title），`literal_query=true` |
| `NX` | `cross_category` | 0 | 69 | 跨类别负样本 |
| `NH` | `same_category` | 0 | 68 | **同类硬负样本**（按视觉相似度相邻排列后取邻位） |
| `NI` | `image_query` | 0 | 18 | 图片查询负样本（A 的图 → 别的类别的 B） |

> **隐私处理**：素材里有一张「学生请假条」（含姓名与辅导员签名）**刻意不收**；
> 身份证照片在复制时对**姓名行**打码（`scripts/build_eval_set_v3.7.0.py::REDACT`），
> 其余敏感信息（照片、住址、身份证号）原图已由上传者遮蔽。

### 10.3 怎么用

```bat
:: 1) 结构自检（不加载模型）
venv\Scripts\python.exe scripts\calibrate_thresholds.py --stats --eval-set eval\eval_set_v3.7.0.json

:: 2) 三口径 A/B（legacy / v2 / v2+）
venv\Scripts\python.exe scripts\calibrate_v2.py --eval-set eval\eval_set_v3.7.0.json ^
    --out ..\docs\review\scoring-v2-ablation-v3.7.0.md

:: 3) 重新生成（改清单后）
venv\Scripts\python.exe scripts\build_eval_set_v3.7.0.py
```

`calibrate_v2.py` 对本集有三条专门处理：

1. **字面查询不参与阈值标定**（`literal_query=true` 被排除），否则分数天然接近 1.0
   会把 Precision 抬到接近 1、把建议阈值压低；字面能力单列「手动阈值通过率」；
2. 报告增加**负样本切片**（跨类 / 同类 / 图片查询的均分与越阈值率）与
   **`P@硬负`**（只把同类负样本计入分母）；
3. 若出现 `auto < manual`，报告会显式警告 —— 这是「负样本偏易」的信号。

### 10.4 与 v3.5.0 集的关系（引用时别搞混）

| 项 | v3.5.0 集 | v3.7.0 集 |
|---|---|---|
| 数据来源 | 生产库 6 件真实物品 | 素材图 70 件（人工认物 + 人工写查询） |
| 可复现性 | ❌ 依赖本机 uploads + db | ✅ 图片随仓库分发 |
| 类别覆盖 | 4 类（3 类无正样本） | 7 类全覆盖 |
| 字面查询 | 0 对（被硬约束排除） | 70 对（单独统计） |
| 用途 | **生产阈值标定**（真实业务分布） | **口径相对比较 / 覆盖补盲 / 可复现回归** |

> ⚠️ **不要把 v3.7.0 集标出的阈值直接回填生产**：它的查询与标签同源、负样本仍以跨类为主，
> 分布比生产乐观。生产阈值继续以 v3.5.0 集（真实分布）标定。

### 10.5 遗留局限

- 每件物品只有**一张照片**，因此仍**无法构造真实的 img→img 正样本**
  （同图自比恒为 1.0，属退化对，见 §7.4）；`NI` 只做负样本；
- **同义表达**盲区已由 `app/utils/synonyms.py` 部分覆盖（13 组，如 校园卡≡一卡通、课本≡教材）。
  但词典只解决「叫法分歧」，不解决「实例区分」：本集 7 对受词典影响，其中 2 对是同类负样本
  （课本 × 办公软件教材），故同义命中只放行标题通道、加分打 3 折；
  未收录的长尾同义词仍会走「门控关闭 + 仅全文向量」这条较弱路径；
- 查询与标签由同一人（AI + 人工复核）在同一次认物中产出，存在**自我一致性偏差**；
  正式发表前建议请第二人复核 20% 标签；
- 素材图多为「桌面上拍一张」的构图，背景单一，比生产照片更易检索；
- 物品命名（`title`）由认物归纳而非发布者填写，措辞会比真实用户更规范。
