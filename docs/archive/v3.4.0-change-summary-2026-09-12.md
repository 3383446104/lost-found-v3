## 2. 代码变更（已冻结）

### S1 数据与模型层
| 项 | 内容 |
|----|------|
| `users.status` | 新增账号状态列 `active`/`disabled`/`deleted`（原 role 的禁用/注销语义迁出） |
| `items.color_vector` | 新增 27 维 RGB 颜色直方图（JSON） |
| 迁移 | `backend/app/database.py:126-143` 幂等迁移（`PRAGMA table_info` + 条件 `ALTER TABLE`），旧 `role='disabled'/'deleted'` 折算到 `status` 并回写 `role='user'` |
| 备份 | `backend/lost_found.db.bak-20260912` |

### S2 账户状态语义拆分（C2）
- `role` 收敛为 `user`/`admin`；禁用/注销 = `status`
- `toggle_status` 只翻转 `status`、保留 `role`
- 登录按 `status` 分流：`disabled` → 403「账号已被禁用，请联系管理员」；`deleted` → 403「账号已注销」
- `GET /api/me`、登录/注册响应 `user` 增加 `status`

### S3 匹配性能与异步（R4 / R5）
- **R4** 颜色特征持久化：发布/换图时计算并写入 `items.color_vector`，匹配时优先读取、缺失时回退现算
- **R5** 邮件与自动匹配通知改经 `BackgroundTasks` 异步投递

### S4 路由 / 异常 / 请求模型（R6 / R7 / R9）
- **R6** 物品路由统一采用 `{item_id:int}` 路径转换器，消除路由匹配顺序隐患
- **R7** 去除静默吞异常，关键路径显式日志
- **R9** 请求体改 Pydantic 宽松模型，非法参数维持 **400**（非 422）

### S5 清理与版本（R10 / O2）
- **R10** 依赖与配置清理（移除失效 CORS 配置项）；`APP_VERSION = "3.4.0"`
- **O2** 管理员不能禁用/删除**自己**（target==current → 400）；允许操作其他管理员

### 前端
- 仅路由守卫：`router/index.js` 判定字段由 `user.role === 'disabled'` 改为 `user.status === 'disabled'`
