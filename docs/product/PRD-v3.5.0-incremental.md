## 1. 问题陈述（精简，基于已核实事实）

系统当前声称支持「以文搜图」（SRS `FR-MATCH-02` ✅），但**实测与代码核实表明该能力当前名不副实**：

1. **文本塔被截断**：`open_clip ViT-B-32` 文本塔上限 77 token，**实测**（`SimpleTokenizer`，编码后解码回读）**约 37 个汉字完整、38 字起开始丢弃**（纯汉字串；中英混排或含标点会更早触顶），典型中文物品描述极易超限，"描述越详细越准"在中文场景下退化为"写多了也无用"。**换用 Chinese-CLIP 后**：文本塔 `context_length=52`（`cn_clip/clip/utils.py::tokenize` 实为 `[CLS] + tokens[:context_length-2] + [SEP]`），即 **≤50 汉字完整编码，超出部分仍会被截断**——较旧模型（约 37 个汉字）触顶改善显著（**约 37 → 50，可用长度约 +13 汉字**），但**并非无限**。
2. **文本塔分布外**：`ViT-B-32 / laion2b_s34b_b79k` 为**英文**预训练，对中文属分布外输入，语义编码质量不可靠。
3. **跨模态从未启用**：`compute_weighted_similarity()`（`clip_service.py:87-161`）只计算 `img1·img2`（0.50）、`text1·text2`（0.30）、`color1·color2`（0.20）三个**自相似度**，**从不计算 img·text**。即：用户输入文字时，系统实际是在比对**查询文字 vs 物品自带的 title/description 文本向量**——若目标物品几乎没写文字、只有一张图，则**永远搜不到**。所谓"阶段5 交叉验证"（`clip_service.py:154-159`）也只是拿 `img_sim` 与 `text_sim` 两个自相似度比大小，**CLIP 的图文对齐能力一次都没用上**。

**用户后果**：失主只记得"黑色皮质钱包，有拉链，里面夹着一张校园卡"，说不出标题、也找不到图片，**当前的"文字描述"检索实际上帮不上忙**。

**现状数据规模（实测）**：`backend/lost_found.db` 共 **6 条物品**（全部有图有描述、均为 `active` + `approved`；类别分布 电子产品 3 / 钥匙门禁 1 / 证件卡片 1 / 书籍文具 1），另有 85 条匹配记录、54 个用户。因样本极小，**阈值标定必须依赖人工构造的评测集，且结果存在小样本局限**；同时 `POST /match` 仅扫 6 个候选，性能目标（Q7 的 P95<2s）天然满足。

首页 `HomeView` 现有输入框占位为 **"搜索关键词…"**，其行为是 **`title/description` 的 LIKE 精确关键词匹配**（非语义）。用户极易把**描述性长句**输入此处并得到差结果，从而对新能力产生负面印象。**Q4 裁决**：首页直达入口（§4.2）+ 该 keyword 框文案澄清**合并为同一条 P0**——用户把长句输进 LIKE 框会直接砸掉新功能口碑，两件事必须同批交付（见需求池 **P0-7**）。

## 5. 换模型后「用户可见」的影响（重点）

> ⚠️ 本节是**产品/体验口径**，不是技术说明。

### 5.1 匹配通知里的「相似度 XX%」——口径整体变化，阈值必须重标定

**现状**：匹配通知文案为 `与新发布的物品 '…' 相似度 {:.2%}`（`match_service.py:140/159`）。阈值来自 `config.py`：`MATCH_THRESHOLD_MANUAL=0.20` / `MATCH_THRESHOLD_AUTO=0.65` / `MATCH_THRESHOLD_EMAIL=0.75`（另有 `MAX_AUTO_MATCH_NOTIFICATIONS=3`）。

**问题**：这三个阈值是为**旧模型**的相似度分布标定的。Chinese-CLIP ViT-H/14 的相似度分布与旧模型**不同**（尤其新接入的 img·text 跨模态分数分布与旧的"文本自相似"完全不同）——**沿用旧阈值会直接放大或掐死自动推送量**：
- 偏松 → 用户被无关**匹配通知淹没**（通知与邮件轰炸），信任度下降；
- 偏紧 → 审核通过后**一条通知都收不到**，功能形同关闭。

**产品侧容忍口径（要求，具体数值由评测集标定）**：

| 层级 | 场景 | 产品容忍口径 |
|------|------|------|
| **自动推送**（auto） | 站内「[匹配通知]」 | 新物品推送 **0–3 条**（受 `MAX_AUTO_MATCH_NOTIFICATIONS` 限制）；**合格的匹配必须落在 Top-3 内**；任一用户**不应**在同一短时间内被大量无关物品刷屏 |
| **邮件**（email） | HTML 邮件 | **宁缺毋滥**：每封邮件都应是"高置信"级（人工判定相关）；邮件量应显著少于站内通知量 |
| **手动匹配**（manual） | `/match` 结果列表 | 结果列表排序后，**首位应为真相关**；低分项不得霸屏（列表最多 Top-20） |

> 判定产物：上线后若出现"**大量用户反馈通知无关**"或"**单用户通知条数/单位时间显著上升**" → 判**过松**；若"**审核通过后长期 0 推送且确有对应物品**" → 判**过严**。

### 5.2 历史向量与新向量**不可比**（嵌入空间变了）

重嵌入（用新模型重算历史 `items.image_vector` / `text_vector`）**前后**，同一物品的向量位于**不同嵌入空间**，**不能互相比较**。因此：

- **行为预期**：全量重嵌入**完成前**，新旧向量混用会使匹配结果**失真/噪声化**——旧向量与新向量在同一公式里比对没有物理意义。
- **上线前必须**：对全部历史 `items` 做**一次性全量重嵌入**（`image_vector`、`text_vector` 重算；`color_vector` 27 维不受影响）。
- **灰度期怎么处理（产品口径）**：重嵌入期间**暂停自动推送**（避免用半新半旧的数据给用户发错通知）；重嵌入完成后**统一启用**。**Q2 已裁决**：采用**停服窗口**（停写**且**停读），灰度期置 **`AUTO_MATCH_ENABLED=false`**（见 §8）。
- **回滚隐含成本**：重嵌入会**覆盖旧向量**。若要能"切回旧模型"，**必须保留旧数据**。**Q6 已裁决**：采用**库文件冷备**（`lost_found.db.bak-*`，**不新增备份列**），**回滚 = 切配置 + 恢复冷备**（见 §8 / AC-R3）。
- **历史 `matches` 记录**：`matches.similarity_score` 存的是**旧口径**分数。展示历史匹配时**不得**与新的"相似度 XX%"并列比较（见 5.3）。

### 5.3 相似度数值对用户意味着什么——需要改文案口径

- **现状**：用户看到"相似度 XX%"，会把它当"把握程度/概率"。
- **风险**：换模型后分数整体分布偏移，且跨模态分数与旧的自相似分数**不可直接对比**——用户会**拿新旧分数直接比**，产生"以前 80% 现在 60%，系统变差了"的误判。
- **产品要求（Q3 已裁决；需在验收中体现）**：
  1. 用户可见文案**避免诱导"概率"理解**——**保留百分比 + 免责说明**（如"AI 估算，仅供参考"）；**不改定性标签**（定性方案已否决）。
  2. `MatchView` 现有**图例为硬编码**（`MatchView.vue:71-75` 的 `≥75% 高置信 / ≥50% 中等 / <50% 参考`；`badgeClass` 用 0.75/0.5，见 `:142`）——与后端 `MATCH_THRESHOLD_MANUAL=0.20` **本就不一致**。**Q3 裁决：保留百分比 + 免责说明**（不改定性标签）；**图例改为从后端阈值派生并随 `/match` 响应下发**——`legend.high = MATCH_THRESHOLD_AUTO`、`legend.mid = MATCH_THRESHOLD_MANUAL`，图例永久跟随阈值，消除两套魔数。
  3. 换模型**过渡期**不得在同一界面同时呈现新旧口径分数。

### 5.4 已知限制（Known Limitation）：中文描述 >50 汉字的尾段不被文本特征覆盖

- **事实**：新模型文本塔可用窗口 = **50 汉字**，**超长静默截断、不报错**（分词器已实测，依据见 AC-F2）。物品发布/编辑时把 `f"{title} {description}".strip()` **整体**送入文本塔（`items.py:126` / `:392`；查询侧 `:508` 同理），因此**物品描述超过 50 汉字的部分对文本特征毫无贡献**，且用户与系统均**不会收到任何提示**。校园失物描述（含颜色/材质/内含物/时间地点）极易超过 50 字。
- **产品建议（**建议**，不断言实现）**：
  1. **引导前段**：在发布页与 `/match` 描述输入处提示"**把颜色、材质、特征、内含物等关键信息写在前 50 字内**"（与 P1-3 同一动作）；
  2. **可选字数提示**：输入超过 50 字时给出**温和提示**（如"超出部分可能不影响匹配"），**不强制阻断**；
  3. **本次不做**：不改变匹配行为、不引入"分段/多窗口编码"等改动（截断/分段属设计决策，已分开挂架构师，且超出本增量范围）。
- **结论**：本条限制**不影响 v3.5.0 能否上线**——它**不改变匹配行为**，产品侧仅以**用户引导**缓解；匹配质量的核心保障仍是 AC-F2 的 33~48 汉字验收区间。

### 7.5 跨模态一致性惩罚验收（Q8 裁决）

- [ ] **AC-C1**：惩罚**只降权、不提权**（任何物品不因该规则加分）；单次**最大对折**（下界 ×0.50）；对 `cc` **单调**；可由 **`CROSS_PENALTY_ENABLED`** 一键关闭（关闭后与"不惩罚"等价）
- [ ] **AC-C2**：**触发门限** `CROSS_PENALTY_SELF_HIGH`（`0.55`）与**下界**（`0.50`）均为**初值**，须经标定脚本 **`--grid`** 扫描后回填，**不得表述为"已定稿"**
- [ ] **AC-C3**：回填的参数组合**必须满足 `Recall@3 不下降` 断言**；若不满足 → 判为**误伤真实匹配**，**优先提高触发门限（更保守）**，仍不满足则**关闭该规则**
