## 1. 目的与方法

### 1.1 目的

v3.5.0 引入中文模型与跨模态四通道打分，权重（`W_IMG_IMG` / `W_CROSS` / `W_TEXT_TEXT` / `W_COLOR`，跨模态内 `W_CROSS_T2I` / `W_CROSS_I2T`）与分层阈值（`MATCH_THRESHOLD_MANUAL / AUTO / EMAIL`）在设计阶段**均为初值**，须经评测收敛。本报告记录标定过程与结论。

### 1.2 方法

`calibrate_thresholds.py` 对评测集逐对计算相似度 → 画 PR 曲线 → 按目标指标取阈值 → 计算 Recall@1/3/5/10 → 可选权重网格搜索。

阈值取法（设计 §5.5）：

| 参数 | 取法 |
|------|------|
| `MATCH_THRESHOLD_AUTO` | Precision ≥ 0.90 的最低分位 |
| `MATCH_THRESHOLD_EMAIL` | Precision ≥ 0.98 的最低分位 |
| `MATCH_THRESHOLD_MANUAL` | Recall ≥ 0.90 的最高分位 |

**阻塞判据**：`Recall@3 < 0.90` → 阻塞性发现，须上报（脚本已实现该判定并在冒烟中成功触发）。

## 2. 评测集结构校验（真实数据）

`calibrate_thresholds.py --stats`（**不加载模型**，纯数据校验）实测输出：

| 指标 | 实测值 |
|------|------|
| 总对数 | **60** |
| 正样本 / 负样本 | **30 / 30** |
| `query.image` 非空 | 20（img→text **8** ｜ img→img **12** ｜ img→mixed 0） |
| 纯文查询 | 40 |
| `target.text = null` | 12 |
| **退化正例（同图自比）** | **6 → 已从标定计算剔除** |
| **有效标定集规模** | **24 正 / 30 负（n=54）** |
| 查询文本长度 | min 11 ｜ max 36 ｜ **>50 字 0** |
| 正样本标题词泄漏 | **0** |
| 引用图片存在性 | 6 个引用，**缺失 0** ⚠️（**仅本机成立**，见 §2.1） |

### 2.1 ⚠️ 本报告的「缺失 0」**不具备可分发性**

实测的「6 个引用，缺失 0」**只在持有生产数据的机器上成立**。本评测集**不是自包含的**：

| 依赖 | 位置 | 版本控制状态 |
|------|------|:--:|
| 6 张物品图片 | `backend/uploads/*.jpg` | **未跟踪**（`uploads/` 被 `.gitignore` 忽略） |
| 6 条物品记录 | `backend/lost_found.db` | **未跟踪**（2026-09-14 `git rm --cached`，隐私取舍） |

**在全新克隆上执行 `--stats` 会报「6 个引用，缺失 6」，评测集无法运行。** 复现方式见
`backend/eval/README.md` §1.1（恢复生产数据，或按该 README §5 用自己的数据重建评测集）。

> 因此：**§2 的全部结构统计、§3 的退化对自检、以及 §4 的管线冒烟，其有效范围都是「本机」**；
> 不应被读作「任何环境均可复现的结论」。

**解读**：
- **构造式评测集**：实测全库仅 6 条真实 item（`items_total=6`、`items_with_image=6`），抽样不可行，故为构造（详见设计 §5.5、评测集 README §7.4）。
- **无 >50 字查询**：与「Chinese-CLIP 中文塔可用 50 汉字」的文本上限一致，评测集未越界。
- **标题词泄漏 0**：正样本查询**未**直接抄用目标标题，避免虚高。
- **正负 24/30 略不平衡为有意保守**：负样本偏多只会使 `Precision ≥ 0.90` 更难达到 → `auto` 阈值更高 → 线上更安全。

## 3. 退化对排除与通道接线自检（真实数据）

`calibrate_thresholds.py --degenerate-check` 实测：

| 用例 | query 图片 | target 图片 | same_file | sim_ii | score |
|------|------|------|:--:|:--:|:--:|
| P25 | `uploads/079e84f2…jpg` | 同左 | True | **1.0** | 1.0 |
| P26 | `uploads/e388ddd1…jpg` | 同左 | True | **1.0** | 1.0 |
| P27 | `uploads/e83544a7…jpg` | 同左 | True | **1.0** | 1.0 |
| P28 | `uploads/69473b44…jpg` | 同左 | True | **1.0** | 1.0 |
| P29 | `uploads/d75c22bc…jpg` | 同左 | True | **1.0** | 1.0 |
| P30 | `uploads/17748f0f…jpg` | 同左 | True | **1.0** | 1.0 |

→ **共 6 对，全部 `sim_ii == 1.0`：`sim_img_img` 通道已确认接通。**

**为何排除**（架构裁决 A，见设计 §9）：同图自比恒为 1.0，其「命中」是**平凡真**，会把 Recall 虚高、并把 `auto` 阈值向下拖低，污染标定。故该 6 对**仅作通道接线自检**，**不计入** PR 曲线 / Recall / 权重网格。

**附带结论（架构裁决 B）**：「img→img **真实**正样本在当前素材下不可构造」（每物仅 1 张图片，无同一实物的第二张图），故不伪造；结论已同步至 `backend/eval/README.md` §7.4 与设计 §9。

## 6. 阻塞原因与解除条件

### 6.1 阻塞原因（客观、可复现）

真实 Chinese-CLIP **ViT-H-14 权重大小约 3.83GB**，本机实测下载不可行：

| 源 | 实测 |
|------|------|
| `huggingface.co` | **不可达**（代理 502） |
| `hf-mirror.com` | ≈ 28 KB/s |
| ModelScope | ≈ **472 KB/s** → 约 **2.2 小时** |

且 ModelScope 直连需先 `pip install modelscope`（当前 venv 未安装）。
→ **本轮无法加载真实模型，因此无法产出真实标定数值。**

### 6.2 解除条件（任一即可）

1. 在网络条件允许处下载权重，置 `CLIP_CN_CKPT_PATH` 指向本地 `.pt`（**运行期零网络**，推荐）；或
2. 安装 `modelscope` 并预留约 2.2 小时完成 `CLIP_CN_USE_MODELSCOPE=True` 下载。

### 6.3 解除后须执行的命令

```bash
# 在 backend/ 下
venv/Scripts/python.exe -m pip install modelscope          # 仅方案 2 需要
venv/Scripts/python.exe scripts/reembed_all_vectors.py --dry-run   # 先干跑看 ETA（不写库、不冷备）
venv/Scripts/python.exe scripts/reembed_all_vectors.py             # 真实重嵌入（自动冷备 + 断点）
venv/Scripts/python.exe scripts/calibrate_thresholds.py --grid --out docs/review/threshold-calibration-v3.5.0.md
```
